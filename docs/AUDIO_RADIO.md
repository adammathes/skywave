# Audio and radio

The radio is half the experience. It plays **real music the user owns or real stations that broadcast**, organized into era-tagged stations you flip through from the dashboard. The repository contains no audio and no lyrics; presets are URLs and metadata only.

## Stations
```
Station(
  id: "radioparadise_main", name: "Radio Paradise Main Mix", era: "mixed",
  format: "eclectic album rock",
  source: Stream(urls: ["https://stream.radioparadise.com/mp3-128", ...],
                 homepage: "https://radioparadise.com/listen/stream-links", codec: Mp3, bitrate_kbps: 128,
                 terms_checked: "2026-10-27", verified: false)
        | Files(folder_hint: "yacht-rock"),
)
// later: Youtube(playlist: "...") (web only), shuffle_seed for files ("already playing")
```
A station's name is the real service's own channel name (a fact); the dash shows it as it is. There is no DJ or ident audio: station idents are visual only. A `RadioPreset` file (`assets/radio/<era>_<scenario>.ron`) lists the stations of one era and scenario (`crates/audio/src/station.rs` has the format and its validation). The user's settings switch stations off, add streams by URL and pick a preset per scenario. The dash shows the station name and the toast its format; the current track title (ICY metadata from streams, tags from files) comes later.

### Sources
1. **Files** (native + web). The player's own music is not on the dial: it is the **deck**, a second source beside the radio (a tape deck, CD player or MP3 player by the world's era; "The deck" below). Web: built. Native: built: the music folder (`--music DIR`, else a `music` folder beside the executable, else `~/Music`) and the folders picked from Audio › Music library (the platform's folder dialog) or dropped on the window, remembered, scanned into the same `audio::deck::Folder`s ("Native music folders" below), MP3 decoded with the native radio's `nanomp3-core`. No `symphonia` (MPL-2.0 is out).
2. **Streams** (native + web). Internet radio over HTTPS (Icecast/SHOUTcast MP3/AAC). Native: a hand-written HTTP/1.0 GET over `rustls` feeding `nanomp3-core` (MP3 only; ADR 0006); ICY metadata parsed for titles. Web: an `<audio>` element driven from JS glue (streams work without CORS for playback; titles need CORS-enabled stations, otherwise none). Presets ship with a handful of well-known public stations per era/format whose terms allow listening (e.g. listener-supported stations with public stream URLs); each preset records the homepage and the date checked. Nothing is rehosted.
3. **YouTube** (later, web only). Official IFrame Player API with user-supplied playlist IDs; the player element must remain visible (ToS), so it is rendered as the "radio display" in a corner of the page. No audio-only tricks.

### Switching
Next/previous station, radio off, volume. Switching plays a 0.5 s dial sweep (static, a whistle, a squelch click) then the new station. Station list and current track on the dash display and as a small HUD toast. Stations persist across sessions; the last station is restored.

### As built (M3, web first)
- **`crates/audio`** (std, platform-neutral). `Radio` is the switching state machine: `Off`, `Tuning { from, to, t }` (`TUNE_SECONDS`, 0.5 s, of the dial sweep), `Playing { station }`, `Error { station, reason }`. Next/previous from off resume the last station; `\` is the power button. It emits `RadioCommand`s (`Play { url, token }`, `Stop`, `Volume(f32)`), counts its tunes (`Radio::tunes`, which the app copies into `AudioParams::tunes` so the mixer plays the sweep; the automatic move after "no signal" is a tune too) and takes `PlayerEvent`s (`Started`, `Failed`, `Blocked`, each with the token of its `Play`; stale ones are ignored). A failed URL moves to the station's next URL; when none is left the station is in `Error` ("NO SIGNAL" on the dash and in the toast) for `NO_SIGNAL_SECONDS` (2 s), then the radio tunes the next station up the dial by itself. A station that failed is remembered for the session (by id) and skipped by next, previous, power-on and the automatic move, until it plays again; when every station has failed, "NO SIGNAL" stays and the dial turns plainly, so the user can retry. `RadioSettings` (volume, power, last station, disabled stations, added streams, preset per scenario) is the `radio` section of the settings JSON. Native will consume the same commands.
- **`app::radio`**. The built-in presets, the keys (`]` `[` `\`, d-pad right/left/down, while the radio is the source; `'` or Back held + d-pad down switches to the deck), the toast ("1/7  Radio Paradise Mellow Mix" over its format, 3 s; "Press any key for radio" while the browser holds playback), and the dash: in the cockpit view the radio display quad's corners are projected to the screen and the station name is drawn there as HUD text in the display's glow color, scrolling a character at a time when it does not fit. The radio is off when a session starts, always: nothing plays until the power key, whatever the last session ended with (no stream, and so no station's ad, ever plays unasked). The last station is restored so that power resumes it. Still scenes never start it (screenshot goldens stay silent). Settings → Audio (one page with the sound effects' volumes): master, engine, world and radio volume, mute, preset (per scenario), Stations (on/off per station and added stream), "Add stream URL" (web: a text prompt; `https://` only), "Remove added streams". The master volume scales the radio too and mute silences it; while a station plays, its volume setting is `AudioParams::radio`, which ducks the engine and world buses.
- **Web** (`platform-web` + the radio block of `web/index.html`). One hidden `<audio preload="none">` element: `Play` sets its `src` and calls `play()`; `error` events, rejected plays and a stream (not a file: files report their errors) that neither plays nor errors within 10 s come back as `failed`, a `NotAllowedError` (no user gesture yet) as `blocked`, retried on the next key, click or touch (the key that dismisses the help card counts). The dial sweep is not played here: it comes from the mixer through the sfx worklet, like the engine. Media Session metadata carries the station name. `window.skywaveRadio` is the debug handle (`.log`, `.state`, `.audio`). Nothing is fetched until the user tunes a station.

- **The deck** (`audio::deck`, `audio::music`; `app::deck`, the readout in `app::ui::readout`; web glue in the music block of `web/index.html`). The player's own music, as a second source beside the radio (`Source::Radio` or `Source::Deck`). Its name follows the world's era (`Kind::for_year` of the scenario's `year`): **TAPE** for worlds up to 1989, **CD** for 1990–2009, **MP3** from 2010. Like the radio it is silent at the start of every session: nothing plays until a key.
  - *Library.* "Music library" on the Audio page opens `showDirectoryPicker` where the browser has it (Chromium), else a folder input (`webkitdirectory`, every browser); folders dropped anywhere on the page work too. Every picked or dropped folder joins **one library**; a drop of loose files is one album called "Mixtape". `audio::deck::Library::build` indexes it as Artist › Album › tracks from the folder layout (`Artist/Album/NN Title.mp3`, the common music-app export: a file's folder is its album, the folder above it the artist; files right in the picked folder are an album named after it; the title is the file name less its extension and its leading track number, "03 - Title" or "1-03 Title", which also numbers it), and the tags override: `TIT2` title, `TPE1` the track's artist, `TPE2` (else the one `TPE1` all its tracks share) the album's artist, `TALB` the album (a folder whose files name two albums is two albums), `TRCK`/`TPOS` the order, `TYER`/`TDRC` the year (the ID3v2 parser reads those frames too, in v2.2's three-letter ids as well). Tracks play by disc, track number, then file name; albums sort by artist, year and title, case-insensitive. Names are printable ASCII, as the HUD font draws them: Latin-1 letters lose their accents ("Café" reads "Cafe"), other characters are left out, and a name with nothing left falls back to the folder's or file's name ("Unknown Artist", "Track 3"). At most 4096 tracks. The page keeps the `File`s; the game gets each file's key, its path in the folder, its size and first 64 KiB (plus 4 KiB where its audio starts, when cover art in the tag pushes that further), from which `audio::music::probe` reads the tags and the length (the Xing/Info or VBRI frame count, else the first frame's bitrate over the file size; other formats count as 240 s). Picked folders are remembered as handles in IndexedDB where the browser can store them; next session they are back in the library at once if the browser still grants reading them, else the item reads "Pick music folder again" and asks one folder's permission per press. Where handles cannot be stored (the folder input), the toast says so when the folder is added ("pick it again next time"). A folder without a handle (the folder input, a dropped folder, loose files) keeps an id made from its name and its files' paths and sizes, so picking the same one again replaces it rather than listing every album twice. The picker needs a key or a click (a browser's user activation); after a gamepad press the game says "Use the keyboard or mouse, or drop a folder on the page". "Remove music folders" on the Audio page, and "Remove <folder>" on its Library page, forget folders for good. Nothing is uploaded or sent anywhere.
  - *Transport* (`audio::deck::Deck`, on the radio's keys while the deck is the source). Play/pause on the power key; next/previous track (previous within `PREV_RESTART_S`, 3 s, of a track's start goes to the previous track, later it restarts the track); next/previous album, an album being a tape or a disc, with a toast ("TAPE  Night Shift - Coastline" over "Side A  1983  9 tracks"); the Audio page's Library lists every album as "Artist - Album", and selecting one plays it (and makes the deck the source). An album key on the radio puts the tape in: the deck becomes the source on that album. It sends the radio's commands to the same player (`PlayFile { key, start_s }`, `Stop`; pause is a `Stop` and play a `PlayFile` from the second the deck counted, while the player said it was playing) with tokens of its own (the high bit set), so the radio and the deck each ignore the other's reports. A track that ends plays the next; one that fails is skipped; every track failing in a row stops the deck ("No track played").
  - *Modes* (the Mode key cycles them, or Audio › Deck mode): **Normal** plays album order, then the next album in artist order, and wraps from the library's last track to its first. **Shuffle** plays the whole library in a seeded shuffle (the library's keys hashed, and the pass): every track once before any repeats, each pass its own order, and a pass never starts with the track that just ended; switching into it starts the pass with the track loaded. **Continuous** is the library as an already-playing station (PR 34's seeded broadcast, `music::Playlist`): play, coming back from pause or switching into the mode lands where the broadcast is by the deck's clock, mid-track; next/previous and album picks move the broadcast along, so it stays where you put it.
  - *Persistence.* The `deck` part of the `radio` settings section (`DeckSettings`): source, mode, the track loaded (its key), the second into it (whole seconds when paused, five-second steps while playing, so a playing deck writes the settings at most every 5 s) and the Shuffle pass. Next session the source is selected again, the track and second are loaded when its folder comes back, and the first press of play resumes there (Continuous lands on that second too, and the broadcast goes on from it); nothing plays before a key.
  - *Readout* (`app::ui::readout`). A block at the top right of the driving HUD, the corner opposite the minimap, under the clock and the source's toast: a badge (TAPE, CD or MP3; RADIO) with the mode (unless Normal) and the transport state beside it (`>` playing, `||` paused, `...` tuning, `OFF`, `NO SIGNAL`, `PRESS A KEY`), then three lines: artist, album, song for the deck; the station's name and what its stream says is on for the radio (natively its ICY title, `App::set_now_playing`; the web player reads none, since streams send them only to players that ask, which the page's `<audio>` cannot, so the web shows the station's format). A line longer than the block (28 characters at UI scale 1, half the safe area's width at 2) scrolls a character at a time. It shows for 6 s after anything changes (a transport or source key, a new track or station) and fades out over 1 s. It stays inside the safe area and clear of every other HUD quad at UI scales 1 and 2, at 1280×800 and 1920×1080 (a test checks every item's box as drawn), leaving out its lower lines while a long status toast at the bottom left would reach it. The F3 overlay draws over it. In the cockpit the dash display shows "Artist - Title" for the deck, scrolling, as it shows the station for the radio.
  - *Sound.* Each transport press that moves the mechanism (play, next, previous, an album) plays the deck's click (`audio::synth::deck`, on the ui bus at the radio volume, `AudioParams::deck_clicks` and `deck_kind`): a tape deck's key clunking down (a 110 Hz thump and a latch click 60 ms later) and its capstan motor spinning up (0.22 s); a CD player's sled seeking in five quick ticks over a faint disc whine (0.3 s); an MP3 player's soft button click (40 ms). Pinned by WAV hash in `mixer::tests`. The dial sweep stays the radio's.
  - Playback is the radio's `<audio>` element on an object URL: it reads the file from disk and decodes as it plays, where `decodeAudioData` would hold every track as PCM. MP3 plays everywhere; AAC/M4A, Ogg/Opus, FLAC, WAV and WebM where the browser decodes them (`canPlayType`). The page's `skywaveRadio.readout` holds the readout's text (badge and status, then the lines), reported with the state whenever either changes. Known: a hidden tab goes quiet at the end of the current track until it is shown again (the game's frame loop advances the deck); every remembered folder is read again at page load.
  - Tests: the library from a folder layout and from tags, mixtapes, the three modes (order, no repeats in a Shuffle pass, the Continuous resume math), the transport's edges (previous within 3 s, an album's last track to the next album, the library's end, failures), restore (`audio::deck`); the keys, toasts, era and the settings round trip (`app::deck`); the pad-only flow, the keyboard keys and the fade, resuming next session at the same second, and the readout against every other HUD quad at both scales and both resolutions (`app::ui::tests`); the click's WAV hash (`audio::mixer`); and `node tools/screenshot/shoot.mjs --music`, which picks a generated two-album library (silent MP3s with tags) through the folder input and drops a loose file on the running page, then presses play, next, next album, mode and pause and checks the readout's text and the player's log.

## Presets
Real stations whose broadcasters publish their stream URLs for listening in other players; nothing is rehosted. `verified` stays `false` until the owner has listened from the game.

**The ad-free rule.** Every preset station is ad-free and its terms allow third-party players: listener-supported, public or college broadcasters (and other non-commercial ones) whose published stream URL plays music or their own programming from the first second, with no pre-roll and no inserted mid-roll. Commercial aggregators are out however their streams are labelled: their stitching servers put a pre-roll in front of every connection (181.FM, the first presets, answered as `Server: DAS` with `X-DAS-SessionId`, sent a minute of credit-card spots at a burst before the music, and titled it "THIS STATION WILL CONTINUE AFTER THIS BREAK"; it is the owner's "forced ad at the start"). Underwriting that a public station reads on air within its own programming is not an inserted ad; a spot the stream's server inserts is. Each station carries a `// ad-free: <date>, ...` comment just above it in its preset saying how that was checked and where its terms are; the checker warns about a station without one.

How a station is checked for ads, before it goes in and when its note is renewed:
1. Two cold starts of at least 60 s each with `node tools/check-streams.mjs --url <url> --kbps <n> --listen 60 --save <dir>` (`<dir>` outside the repository, which the checker enforces: recorded broadcasts are not ours to commit; it reads a minute of wall time and of audio, prints the ICY titles as they change and keeps the audio with the ICY blocks taken out).
2. No warning from it: it flags the response headers, every redirect hop's host (it follows redirects itself to see them) and ICY titles of ad insertion (`Server: DAS`, `X-DAS-*`, `X-Ad*`, AdsWizz, Triton/StreamTheWorld and similar hosts, `adw_ad`/`insertionType`/"advertisement"/"after this break" titles). A burst of many seconds at the start is not proof of a pre-roll by itself (most Icecast servers burst their buffer), but with a station ID or sponsor line it is.
3. Listen to the saved audio, or let a speech recognizer transcribe it and read the loudness per 5 s (`ffmpeg -af ebur128`): an ad is a sudden change of content with a different loudness and a spoken pitch ("... is made possible by ...", a product, a phone number). A DJ talking over the station's own show is not an ad.
4. The terms or stream-links page: the URL is published for listening (a `.pls`, a "listen in your player" link, the station's own listen page), and nothing forbids other players or sites.

**The referer rule.** The game is a web page (`https://adammathes.github.io/skywave/`), so every stream request carries that page as its `Referer` and `Origin`, and must be HTTPS (an `http://` stream is blocked as mixed content). A station whose servers refuse requests from other sites, or whose terms do not allow its streams inside third-party players or sites, does not go in a preset, and we never work around a refusal (no `referrerpolicy`, no proxy). SomaFM is out for this reason: its servers answer 403 to a request with a foreign `Referer`, and it does not allow its streams inside third-party sites. A station that publishes only an `http://` URL goes in when the same host serves the same path over HTTPS.

**The checker.** `node tools/check-streams.mjs` (Node 22; behind a proxy add `NODE_USE_ENV_PROXY=1`) asks for every preset URL the way a browser on the page does: HTTPS only, a browser User-Agent, the page's `Referer` and `Origin`, redirects followed. A URL passes when it answers 200 with an `audio/*` content type and sends at least 5 seconds of audio (`bitrate_kbps` × 5 s of bytes) within 15 s. It prints one line per URL (status, content type, bytes, time to the first byte), a `warn` line for each station without an `ad-free:` note and for each sign of ad insertion, and exits 1 if any URL fails. `--listen <s>`, `--save <dir>` and `--url <url> --kbps <n>` are for checking ads and candidates (above); listening sends `Icy-MetaData: 1` to read the titles, which the page's player does not. All 20 URLs passed with no warning on 2026-10-27.

**Adding a station.**
1. Find the station's own listen or stream-links page (or its `.pls`/`.m3u` playlist) and read its terms: the stream URL must be published for listening, and nothing may forbid other players. That page goes in `homepage`, today's date in `terms_checked`.
2. Check it for ads as above, and write its `// ad-free:` note.
3. Take the `https://` URL (mirrors in order in `urls`), and its real codec and bitrate (the `icy-br` header, or measured).
4. The id is lowercase letters, digits and `_`; the name is the station's own name (at most 48 printable ASCII characters).
5. Run the checker; every URL must pass with no warning. Keep a preset at 5 to 7 stations (a test checks).

Checked on 2026-10-27, each twice from a cold start for a minute: every station below played music or its own live programming from the first second; none had a pre-roll, a break or an ad mark. College stations are live: a cold start can land in a talk show or a news hour (KUCI, KCSB and KXLU did), which is their programming, not an ad.

## Engine and world sound
No recorded audio in v1; everything is synthesized at 48 kHz by the `audio` crate (std; the synth and mixer use no dependencies, only the radio's presets need `ron` and `serde`). The app fills one plain `audio::synth::AudioParams` per frame (`app::sound`, read with `App::audio_params`): engine (profile, rpm, idle and redline, throttle pedal, gear, shift time), forward speed, per wheel (combined slip relative to the tire's peak, load relative to rest, tire speed, grounded, surface under the contact from the collider), curb-kick and wall-hit counters with the last kick's and hit's speed and side of the car (from `world::Bump`) (counted per sim step from `world::Impact`, rising edges only, so no event is lost or doubled between frames), the horn, ocean and bird amounts, the nearest passing NPC cars (`TrafficVoice`: level, pan, heard frequency), the volumes, mute and paused. All synth math is `+ - * /`, `floor` and `sqrt` with a polynomial sine and `exp2` (`audio::synth::dsp`), so a scripted drive renders bit-identically everywhere; its WAV is pinned by hash in `mixer::tests`.

### Engine (`audio::synth::engine`)
One phase at the engine-cycle rate (`rpm / 120`); every partial is a whole multiple of it, so pitch changes never click. Per sample: harmonics 1..N of the firing frequency `rpm × cylinders / 120` with profile amplitudes, a sub-oscillator at half of it, each firing scaled by its cylinder's gain in a per-profile pattern (unevenness gives a cross-plane V8 its burble) times a random variation (largest at idle), exhaust and intake noise (band-passed white noise; exhaust rides the firing pulse, intake grows with throttle squared), all through a low-pass that opens with rpm and throttle. rpm slews with a 20 ms time constant, throttle 30 ms, so 60 Hz parameter steps never zipper. Events: lifting off above half the rev range queues 2–5 exhaust pops (band-passed noise cracks and a 70 Hz kick, 40–160 ms apart) and a closed throttle up high crackles now and then; at 98.5% of the redline under throttle the limiter cuts the sound to 25% at the profile's rate; a change between forward gears dips the level to 50% and closes the filter for the spec's `shift_ms` (the gearbox's torque cut). Idle hunts ±1.2% at 0.8 Hz.

| `feel.engine_sound` | Cylinders | Harmonics | Character |
|---|---|---|---|
| `v8_flatplane` | 8 | 10, slow roll-off | even firing, bright rasp, low-pass 0.7 → 6.7 kHz, crackles; limiter 16 Hz |
| `v8_lazy` | 8 | 7, fast roll-off | uneven firing pattern, strong sub, dark (low-pass 0.4 → 3.4 kHz), fewer pops; limiter 12 Hz |
| `i4` | 4 | 10, flat | buzzy, thin bottom, most intake roar; limiter 18 Hz |
| `v6`, anything else (`default`) | 6 | 8 | smooth, mid-weighted; limiter 15 Hz |

Measured with `tools/audio-preview` (release): idle at 900 rpm puts the strongest component at the firing frequency (60 Hz for the V8s, 30 Hz i4, 45 Hz six) 30–57 dB over its surroundings, with harmonics 2–4 present; a full-throttle sweep keeps the peak within the 20 ms slew of `rpm × 8 / 120` from 110 to 430 Hz; no DC; full-mix peaks stay under -1.9 dBFS. The engine costs ~0.04 ms per 256-frame block and the whole mixer ~0.03–0.05 ms (budget 0.3 ms).

### World (`audio::synth::world`)
- Tire squeal: white noise through two resonant band-passes (~780–1100 Hz wandering, and 2.15× that), level `smoothstep(0.9, 1.7, slip)` × tire speed (full at 4 m/s, so a burnout squeals) × load; asphalt full, concrete 85%, grass none. Left wheels lean left, right wheels right.
- Rolling: leaky-integrated (brown) noise low-passed at `90 + 10 × speed` Hz, by the share of grounded wheels on each surface: concrete brighter with a 95 Hz knock every 4.6 m slab joint; grass adds a band-passed swish.
- Wind: band-passed noise per ear (decorrelated), level ∝ speed² up to 45 m/s, with two slow gust LFOs.
- Curb kick: a 50–90 Hz falling thump and a short click, level from the wheel's speed (full at 24 m/s). Wall hit: a 60–90 Hz thud and a soft 45 ms crunch, level from the approach speed. Each leans toward the side of the car it was on (±35% per ear); nothing harsh.
- Horn: two tones a minor third apart (410 and 500 Hz, five harmonics each) brightened by a 2 kHz band-pass, 6 ms attack, 40 ms release; on the ui bus.
- Ambience: an ocean wash (low-passed noise per ear swelling on 12 s and 20 s cycles) by the share of beach and water zones round the car (the car's point twice, eight points 60 m out); bird calls (2–5 swept chirps at 2.6–4.2 kHz, randomly panned, every few seconds) by the share of residential, suburb and park zones, faded in with the sun between -2° and 8°. Both stay well under the road and engine.
- Traffic: the four nearest moving NPC cars within 120 m (`app::npc`), each a pulse at its firing frequency (30 Hz + 4.5 Hz per m/s, times the Doppler factor of the closing speed with the player's car) low-passed at four times that with a little rumble, at its level (6 m over the distance, louder with speed) and panned by its bearing from the camera; levels ease over 80 ms so a voice handed to another car does not click.

- Radio dial (`audio::synth::tune`), on each new `AudioParams::tunes` (a press restarts it): band-passed static whose center sweeps 500 Hz → 4 kHz over the burst with a 7 Hz jitter, sparse crackle pops, all low-passed at 4.5 kHz (the receiver's bandwidth); a faint carrier whistle gliding 2.4 kHz → 260 Hz; at `TUNE_SECONDS - 80 ms` the squelch shuts with a 1.4 kHz click, and the last 60 ms are silent until the station starts. Scaled by the radio volume setting (`AudioParams::tune_volume`), on the ui bus. At the default mix (everything at 0.8) its RMS is ~1.6× (+4 dB) the engine idle's (`mixer::tests`), and its WAV is pinned by hash.

- Green wave chime (`audio::synth::chime`), on each new `AudioParams::waves` (a signal passed on green in a run, `docs/NPCS.md` "Green waves"): one soft bell note, sine with a 3.01× overtone that fades in 80 ms, 12 ms attack. The run (`wave_run`) sets it: the first light E5, barely there (level 0.02, 0.35 s decay; ~0.002 RMS at the default mix, far under the idle), each light after a pentatonic step up and a little louder and longer (+0.011, +0.12 s, up to the eighth), a fifth above from the third light and an octave below from the fifth, so a long run blooms into a warm chord. On the world bus, so it follows the world volume, ducks under the radio and fades while paused. Pinned by WAV hash in `mixer::tests`, which also checks it grows light by light and stays quiet.

No turn-signal click yet: there is no turn-signal action.

## Mixer
`audio::mixer::Mixer`: 48 kHz interleaved stereo `f32`, fixed 256-frame blocks. The synths fill three buses: engine (mono, centered), world, ui (the horn, the radio's dial sweep, the deck's click; menu sounds later); the green wave's chime is on the world bus. Bus gains: engine and world volume (squared, so the slider feels even) × the radio duck × 0 while paused; ui fixed. Ducking: `duck_gain(radio) = 1 - 0.45 × r × (2 - r)` for the radio level `r` in `[0, 1]` (to 55%, -5 dB, under a full-volume radio; ease-out, so half the radio does three quarters of the ducking); the radio integration sets `AudioParams::radio`. Then master volume (squared, 0 when muted), a 10 Hz DC blocker and a soft limiter: a peak follower with instant attack and 150 ms release whose output level bends from unity at 0.6 toward a -0.5 dBFS ceiling (`KNEE + room × (1 - e^(-over/room))`), so nothing clips. Gains move 16% of the way to their target per block and ramp linearly across it. `Mixer::render(&mut [f32])` takes any buffer length and allocates nothing (tested with a counting allocator). Tests: a 60 s render with everything at full tilt has no NaN and peaks under the ceiling; the ducking curve, volume, mute and pause are checked numerically.

### Sinks
- Native (`platform-native/src/sfx.rs`): a `cpal` output stream on the default device at 48 kHz (f32 preferred, any channel count; 256-frame buffers when the device allows, ≈5 ms). The callback owns the mixer; the main thread copies each frame's `AudioParams` into a mutex the callback only `try_lock`s, so the audio thread never waits. No device: silent, with a log line. ADR 0004.
- Web (`platform-web/src/sfx.rs` and the `sfx` script in `web/index.html`): the mixer runs on the main thread after `App::frame`. The page's AudioWorklet (registered from a Blob URL) plays a 16k-frame ring fed by `postMessage`; each frame the game asks `skywaveSfx.wanted(dt)` how much to render (two blocks plus one animation frame ahead of what the context has played, measured with `AudioContext.currentTime`) and pushes a view of wasm memory that the glue copies. The context is created at 48 kHz (the worklet resamples linearly if the browser picks another rate) on the first key, pointer or touch gesture, and resumed by later ones. `window.skywaveAudio` exposes the state, the worklet, and pushed/consumed/underrun counters. No SharedArrayBuffer, so no COOP/COEP headers are needed.
- Radio streams and the deck's files play outside this mixer (an `<audio>` element on the web; natively a ring the `cpal` callback adds after the mixer); they only set the duck level (a station or a track playing ducks the engine and world alike).

### Native streams (`platform-native/src/radio`, ADR 0006)
`radio::Player` takes the radio's commands each frame and hands back `PlayerEvent`s through a channel; the game's thread never waits. Each `Play` cuts the ring (the old station falls silent at once and its thread can no longer write) and starts a stream thread: `http` (one `GET` in HTTP/1.0 with `Icy-MetaData: 1`, `HTTP/1.x` or `ICY` status, redirects but never https to http, `HTTPS_PROXY`; DNS bounded at 5 s, the TLS handshake at the 10 s deadline), `icy` (metadata blocks split from the audio, `StreamTitle` kept), `decode` (`nanomp3-core`, mono doubled, linear resampling to 48 kHz), then the 4 s ring. `Started` once 0.25 s is buffered (the callback waits for as much before playing, and again after running dry). A stream that never started fails at once: refused, an HTTP error, not MP3 (AAC: the three Radio Paradise AAC stations list their channel's MP3 URL second, which native plays; Intergalactic FM publishes its channels in AAC only, and WMXM's server offers only CBC cipher suites, which rustls does not implement, so natively those three show NO SIGNAL and the dial moves on), or no audio within 10 s; `Radio` then tries the next URL, then NO SIGNAL, as on the web. A stream that played and dropped (hung up, or sent no decodable audio for 10 s) reconnects after 0.5, 1, 2, 4, 8 s (reset by 5 s of steady play), then fails. The callback adds the radio at its volume (already scaled by master and mute) with a soft knee above 0.9. The window title shows the station and its now-playing title. `--radio-off` (CI, benchmarks), or no audio device, drops the commands. `cargo test -p platform-native -- --ignored --nocapture every_preset_station_plays` plays 5 s of every preset station.

### Native music folders (`platform-native/src/music.rs`, `radio/file.rs`)
The music folder is `--music DIR` (made absolute, so ids do not depend on the working directory), else a `music` folder beside the executable, else the home folder's `Music` (an absolute `HOME`, or `USERPROFILE` on Windows): the deck's library, laid out as a music app exports it (`Artist/Album/NN Title.mp3`). A background thread scans it at start, with the folders picked or dropped in earlier sessions (below), each once (one inside another is scanned with it). Each folder in it (an artist's, usually) becomes one `audio::deck::Folder` of every MP3 under it (eight levels deep, at most `MAX_TRACKS`, symbolic links to folders not followed, hidden entries such as a Mac's `._*.mp3` resource forks skipped, and files without a readable MPEG audio frame left out), with each file's path given from the music folder (`Artist/Album/01 Title.mp3`), so `Library::build` reads artist and album from the layout as on the web; the MP3s loose in the music folder make one more, an album named after it. An Apple Music (or iTunes) media folder in it (`Music/Media.localized/Music`, `Music/Media/Music`, `Media.localized/Music`, `Media/Music`, `iTunes/iTunes Media/Music`, `iTunes Media/Music`) is scanned first as if it were the music folder, each folder there (an artist's) one of the library's, its paths `Artist/Album/NN Title.mp3`, and the branch leading to it is left out of the rest; so a library past 4096 tracks fills the deck by artist name rather than stopping in one folder, eight levels being far more than the layout's two. Only `.mp3` files are read: AAC (`.m4a`, `.aac`), FLAC, Ogg and the rest are left out without a word (no new decoder, the owner's call). Each file's first 64 KiB (plus 4 KiB where its audio starts, past cover art) goes through `audio::music::probe` for the tags and the length; the track key is the file's full path and the folder's id its path, so the deck's place persists like the web's. At most `MAX_FOLDERS` (1024) folders are read (by name). When the scan is done they reach `App::add_music_folders` in one batch (kept, not announced) and the library is indexed once, folders past its 4096 tracks left out (a few ms at the cap, once, at start-up); nothing plays until a key. The library carries across a world switch like the web's. "Remove music folders" on the Audio page and "Remove <folder>" on its Library page put the folders on an ignore list beside the settings (`music-ignored.txt`, one path a line; delete a line to bring one back), which later scans skip. A `PlayFile` starts a file thread: past the ID3 tag, it seeks to the share of the audio bytes that `start_s` is of the length (exact for constant bitrate, close for VBR), decodes into the same ring as streams (which paces it), reports `Started` after the prebuffer and `Ended` once the file is done and the ring has drained, so the next track never cuts the tail (each file ends with one prebuffer of silence: the callback waits for that much before it plays, so a track entered in its last fraction of a second still plays out and ends); a file that does not open or holds no MP3 audio is `Failed` and the deck skips it. Other formats are left out (MP3 only natively, ADR 0006). **Picking and dropping.** "Music library" on the Audio page opens the platform's folder dialog on a background thread (the frame loop never waits on it): on macOS `osascript -e 'POSIX path of (choose folder with prompt "Pick a music folder")'`, on Linux `zenity --file-selection --directory` where it is installed; without one (or on Windows) a toast says "No folder dialog: use --music DIR or drop a folder". A folder dropped on the window (winit `DroppedFile`) is taken as if picked; MP3s dropped loose are one "Mixtape" album a drop, not remembered (other files dropped are left out without a word). A picked or dropped folder is taken off the ignore list with everything in it, written to `music-folders.txt` beside the settings (one path a line) so the next start scans it again, and scanned on a background thread, as part of the folder it is in when that one is scanned already (so its folders keep their ids and nothing is listed twice); the toast says "<folder>: N tracks in the library", or "No MP3s in <folder>" when it has none. "Remove music folders" also empties `music-folders.txt`. `--radio-off` leaves out the scan, the dialog and drops.
