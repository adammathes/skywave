# ADR 0004: cpal for native audio output

Status: proposed, 2026-10-26

## Context
Native builds (desktop Linux, Steam Deck, Mac, Windows) need one audio output stream for the synthesized engine and world sound (`docs/AUDIO_RADIO.md`, "Mixer"). Talking to ALSA, CoreAudio and WASAPI ourselves is three backends of callback plumbing, device enumeration and format negotiation. The web build uses an AudioWorklet in the page's JS glue and needs nothing here.

## Decision
`cpal` 0.18 (Apache-2.0, ~22k lines across its backends, of which one compiles per target; default features off, so no JACK/PulseAudio/PipeWire hosts). Only `platform-native` depends on it. The stream asks for 48 kHz and a 256-frame buffer; its callback owns the `audio::mixer::Mixer` and reads each frame's `AudioParams` with a `try_lock`, so the audio thread never waits on the game. On Linux it needs `libasound2-dev` at build time (added to CI) and libasound at run time (present on SteamOS and desktops, usually through the PipeWire or PulseAudio ALSA plugin). Without a device the game runs silent.

## Consequences
The `audio` crate stays dependency-free and platform-free; replacing `cpal` (a console port, or a smaller ALSA-only sink for the Deck) touches `platform-native/src/sfx.rs` only.
